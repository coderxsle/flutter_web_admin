## 菜单图标回归本地彩色方案（提交 `0390eb0d`）

**问题**：上游 `11d68ac5` / `bc7ae2d8` 删除 SVG Sprite 体系（`vite-plugin-svg-icons` + `virtual:svg-icons-register` + `GiSvgIcon`），改为 Iconify。但菜单数据里的裸名图标（`menu-analyse`、`menu-home`…）无集合前缀且不以 `icon` 开头，`MenuIcon.vue` 判定不到 → **菜单图标整片消失**。

**方案**：沿用上游 Iconify 机制 + 恢复本地彩色图标（不引回旧依赖）。

**关键事实（以后复用）**
- 自定义图标集：`src/icons/custom-icons.json`，`prefix="custom"`，注册在 `src/icons/index.ts` → `addCollection(CustomIcons)`，由 `src/main.ts` 引入。追加 19 个本地彩色 SVG 后由 38 → **57 个**。
- **裸名图标必须先注册进 collection，再靠 `custom:` 前缀渲染** —— Iconify 的 `Icon` 组件不认没有集合前缀的裸名。
- 本地基线的菜单图标形态是**两层混用**，不是全部裸名：父级（一级）菜单 = 本地彩色裸名；子级菜单 = `icon-park-outline:*`。所以「恢复本地图标」= 只回滚父级，子级保持不动。
- 菜单图标渲染**唯一入口**是 `MenuIcon.vue`（被 `Menu/MenuItem.vue`、`OneLevelMenu/index.vue`、`views/system/menu/index.vue` 复用）。改这一个组件即可覆盖全部菜单渲染点。
- `MenuIcon.vue` 判定顺序：① 裸名（无前缀且不以 `icon` 开头）→ `custom:<name>` @24px ② `icon-park*` / `custom:` → @16px ③ Arco 组件（`icon*` 开头）→ `component :is` @size 24 ④ 其它 Iconify 集合 → @24px。
- `computed` 由 `unplugin-auto-import`（`vite.config.ts` 的 `imports: ['vue']`）全局注入，写 `<script setup>` 时**不需要手动 import**；声明在 `src/auto-import.d.ts`。

**校验**：`custom-icons.json` 19 个图标齐全且 body 非空；菜单图标与本地基线**逐路径 61 条 0 差异**；`GiIconSelector` 的 Custom 页签自动收录新图标。
