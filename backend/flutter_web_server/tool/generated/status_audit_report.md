# zhongyi status 字段核查与 int 化改造报告

> 两轮工作：(1) 核查数据库同步脚本 `status` 是否写反；(2) 按项目约定把 zhongyi 各表
> `status` 由 text 统一改为 int，并同步落库。

---

## 一、结论：写反了，共 1124 行受影响

源库 FastapiAdmin 与目标库 flutter_web_server 的 `status` 语义**完全相反**：

| | 源库 FastapiAdmin | 目标库 flutter_web_server |
|---|---|---|
| 语义注释 | `状态(0:正常 1:禁用)` | `状态（0停用，1启用）` |
| `0` | 正常 / **启用** | **停用** |
| `1` | 禁用 / **停用** | **启用** |

导入脚本直接把源值搬过来（`zhongyi_medicine` 的转换函数还把 `'1'` 当成「启用」），
导致源库中处于「正常」的记录在目标库全部变成「停用」。

### 判断依据（全部为源码原文）

1. 源库列注释 `10月3日备份.sql:8206`：`'状态(0:正常 1:禁用)'`
2. 源库 ORM `module_lxs_zhongyi/medicine/model.py:65`：
   `mapped_column(String(10), default="0", ..., comment="状态(0:正常 1:禁用)")`
   —— 同注释在源库 20 处模型重复出现
3. 目标库模型 `zhongyi_medicine.spy.yaml:29`：`status: int, default = 0  # 状态（0停用，1启用）`
4. 目标库列注释 `tool/generated/schema_comments.sql:926`：`'状态（0停用，1启用）'`
5. 管理端 `frontend/src/views/zhongyi/medicine/index.vue:119,197`：
   `checkedValue: 1, uncheckedValue: 0`、`status === 1 ? '启用' : '停用'`
6. 数据自洽性：源库 `zhongyi_department` / `zhongyi_prescription_template` 的 `is_active` 全为 `'t'`，
   而这些行的 `status` 全为 `'0'` —— `'0'` 就是启用态

### 附带发现：服务层还有一处同类反向判断（已修）

`lib/src/services/zhongyi/zhongyi_prescription_template_service.dart:227`

```dart
// 改前：把「启用」的药品当成停用拒掉，逻辑正好相反
if (medicines.length != medicineIds.length || medicines.any((medicine) => medicine.status != 0)) {
  throw const RestException.badRequest('处方模板引用了不存在或已停用的药品');
}
// 改后：按「0=停用 1=启用」约定，非 1 即视为停用
if (medicines.length != medicineIds.length || medicines.any((medicine) => medicine.status != 1)) {
```

判断依据：目标库约定 1=启用，而该行抛出的错误信息是「已停用」，
说明作者按「0=启用」的源库约定写了条件。

## 二、status 统一改为 int

### 改动前的类型分布

| 模型 | 改前 | 改后 | 语义 |
|---|---|---|---|
| `zhongyi_medicine` | int | int（不变） | 0停用 1启用 |
| `zhongyi_inventory` | int | int（不变） | 0停用 1启用 |
| `zhongyi_bill` | String `'active'` | **int** | 0取消 1正常 |
| `zhongyi_bill_item` | String `'0'` | **int** | 0停用 1启用 |
| `zhongyi_cabinet` | String `'0'` | **int** | 0停用 1启用 |
| `zhongyi_medicine_inventory` | String `'0'` | **int** | 0停用 1启用 |
| `zhongyi_payment` | String | **int** | 0待支付 1已支付 2支付失败 3已退款 |
| `zhongyi_refund` | String | **int** | 0待审批 1已批准 2已完成 |

> `zhongyi_payment` / `zhongyi_refund` 两表原本**没有任何数据**（代码里也只写过 `'paid'`），
> 因此其数值编码是我新定的顺序编号，如与你的设想不同请告知，改起来只是常量替换。

### 涉及文件

**模型（6 个）**：`lib/src/models/zhongyi/` 下 `zhongyi_bill` / `zhongyi_bill_item` /
`zhongyi_cabinet` / `zhongyi_medicine_inventory` / `zhongyi_payment` / `zhongyi_refund` 的 `.spy.yaml`

**迁移**：`migrations/20261004041802070/migration.sql`
Serverpod 自动生成的是 `DROP COLUMN` / `DROP TABLE` 重建（会丢数据），已改写为原位转换：

```sql
ALTER TABLE "zhongyi_bill"
    ALTER COLUMN "status" DROP DEFAULT,
    ALTER COLUMN "status" SET DATA TYPE bigint USING (CASE WHEN "status" = 'active' THEN 1 ELSE 0 END),
    ALTER COLUMN "status" SET DEFAULT 1;
```

其余四张 0/1 表用 `USING (CASE WHEN "status" IN ('0','1') THEN "status"::bigint ELSE 0 END)`；
`zhongyi_payment` / `zhongyi_refund` 用 `CASE "status" WHEN 'pending' THEN 0 ... END`。

**服务层**：`lib/src/services/zhongyi/zhongyi_billing_service.dart`
常量改为 int（`billActive = 1`、`billCancelled = 0`、`refundPending/Approved/Completed = 0/1/2`，
新增 `paymentRecordPaid` 等），`canPay` / `canRequestRefund` 的 `billStatus` 参数与
`canApproveRefund` / `canCompleteRefund` 的 `status` 参数由 `String` 改为 `int`。
`paymentStatus` 字段（`unpaid/partially_paid/paid/refunding/refunded`）**保持 String**，理由见下。

**前端**：`src/apis/zhongyi/index.ts`（`Billing.status`、`Payment.status`、`Inventory.status` → `number`）、
`src/views/zhongyi/billing/index.vue:200`（`record.status !== 'active'` → `!== 1`）

**导入脚本**：`tool/import_fastapi_zhongyi.sql.sh`
`status_tables` 扩到 5 张表（含 `zhongyi_bill`），统一走 `status_value()` 取反，输出不再带引号。

## 四、需要你确认的两点

1. **`zhongyi_bill.paymentStatus` 仍是 String**。
   它和 `status` 是不同字段，取值域是 `unpaid / partially_paid / paid / refunding / refunded`
   五态流程，并且被管理端账单页直接渲染（`record.payment_status === 'paid'`）、
   服务端 `derivePaymentStatus()` 驱动。本次按「字段名为 `status`」的范围处理，未纳入。
   要一起改 int 请说一声，编码我建议 0/1/2/3/4。
2. **payment / refund 的数值编码**是我新定的（见上表），两表当前无数据，调整成本很低。
